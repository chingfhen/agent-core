# Coordinated handoff and closeout

Use for an explicit project-work handoff to a fresh session/agent or a request
to close out a task. The request authorizes relevant KB capture, docs integration,
task maintenance, and operational-lessons review within configured ownership and
local permissions. Honor narrower requests; approval to persist is not approval
to implement, spawn agents, publish, or migrate resources.

## 1. Establish what must survive

Read the affected task/index and relevant existing sources. Identify decisions
and rationale, findings/evidence, deliverables, verified results, unresolved
questions, dependencies, gates, and potentially useful operational learning.
Distinguish observed, reported, inferred, approved, and untested claims. Use only
available conversation/context; do not reconstruct lost history by invention.
Reuse the same findings throughout the review rather than making four summaries.

## 2. Use each owning workflow

Load the available owning skills and perform a bounded evaluation:

- **knowledge-base:** retain reusable findings, evidence, and useful uncertainty
  when capture adds value. Follow its authoring, navigation, and verification rules.
- **project-docs:** integrate settled project understanding into its canonical
  home; preserve intended design separately from current implementation.
- **agent-lessons:** evaluate future behavioral improvements. Reuse the sources
  just saved; use its owning workflows for any additional supporting detail.

Each may produce a valid no-op. Persist supporting sources before adding pointers
or shortening existing detail. KB and docs remain standalone: they do not invoke
this coordinator or each other. Route a claim once to its primary authority and
link useful evidence, rather than propagating identical prose between surfaces.
Lessons review must not recursively start another task handoff.

If a skill is unavailable, report it; do not claim invocation or substitute an
unverified workflow copy. Missing configuration follows that owner's first-use
rules. An unconfigured KB is not an invitation to use personal storage, the task
folder, or a new companion file. Keep safely writable continuation state and
record any material persistence gap instead of blocking all useful work.

## 3. Save the continuation contract

Verify saved supporting files/locators, then update or create the appropriate
tasks. Include goal, deliverables, acceptance, current state, meaningful decisions,
verification, dependencies, next permitted action, and the resume-context map.
Each pointer says what it supplies and when it must be read. Required references
must be accessible for dependent execution; conditional references wait until used.

For multiple tasks, prefer one shared source/effort overview for common intent.
Children identify the exact preceding output they consume and what remains to be
decided from it. Do not resolve later investigations merely to write their tasks.
Reuse an existing task for the same outcome; a new session is not a new task.

Keep essential constraints and a short decision consequence in each task. The
task should be supervisable without reading every reference, while detailed
project truth stays at its canonical source. Preserve stable task paths and update
only affected index entries, including workstream labels and meaningful next actions.

## 4. Verify the handoff or closeout

Read back the affected task, index, and references. Can a fresh agent identify
what to produce, what to read first, what is uncertain, and what it may do next
without this chat? Check links/locators and authority/readiness consistency.
This is a content review, not evidence of a fresh-agent trial.

For closeout, distinguish completed deliverables from incomplete persistence or
verification. Do not claim a failed capture succeeded. If required closeout work
remains, record it as pending with a clearing condition; close only after it is
completed or explicitly waived/cancelled. Independent safe writes may stand after
partial failure. Retry from saved material and finish missing steps without
duplicate captures. Apply the main skill's closure reason and index rules.

## 5. Return a short receipt

Give the exact task/effort path, meaningful supporting changes or no-ops, material
gaps, and next action or closure result. A compact resume cue should let the human
reference the task or workstream in the next session without naming four skills.
