# KB filesystem persistence

Read only for KB maintenance using a durable local or mounted filesystem, including a Git checkout; ordinary recall needs neither adapter nor skill. Apply root and [KB module](knowledge-base.md). Resolve explicit KB/archive locators and established legacy bases; expand ~ only using actual user's home. Do not guess names, use ephemeral sandbox as durable storage, or silently substitute another root. No Git prerequisite. Archive outside KB and not containing it; confirm scope only when relevant. Legacy external knowledge root is read-only in ordinary new workflow.

- Normalize paths and inspect relevant existing parents before mutation; refuse traversal or symlink/junction/reparse indirection escaping authorized roots, file/directory mismatch or ambiguous ownership. Create needed parents lazily; preserve unrelated files.
- Read current contents before editing existing records/artifacts/indexes. Prefer targeted changes; preserve unrelated sections and intervening edits. For substantial replacements use temporary file then atomic replacement when available; atomic rename prevents torn writes, not lost updates, so recheck when concurrency is plausible. Refuse ambiguous collision; match identity or choose a descriptive suffix.
- Save raw UTF-8 Markdown; group related record/index operations when possible. A local write does not imply Git init, stage, commit, push, remote/sharing changes or exclusions. A local Git checkout is not itself backup.
- Selected originals stay in place. Read actual accessible source and verify locator; use revision/content hash when needed to identify changed or previously captured sources. No copy-verify-delete routine. Explicitly authorized original retention/disposition beyond selected-source capture requires exact destination/scope and preservation of original bytes if copied, collision safety and targeted fidelity checks. Never remove the only original or recurse over archive/inbox.
- For explicit managed artifact disposition, verify exact identity, links/index and authorized destination/action. Do not infer destructive permission or create a new discard scheme. Verify recoverable relocation before any authorized removal; respect stronger local gates.
- Search selected KB paths by bounded filename/text results, including hidden context roots when necessary; exclude raw/archive and unrelated files. Do not require a particular shell or unavailable tooling.
- Verify successful targeted writes and affected navigation; additional reads only where write evidence is insufficient. Substantial rewrites check preservation and concurrency. A failed index write leaves valid record writes intact; retry only missing work. Report exact durable local paths and limitations, not remote publication or successful capture from temporary drafts.
