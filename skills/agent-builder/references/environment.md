# Environment — expected external service access

Read after the Agent Builder root for requested environment setup, check, repair or maintenance, or when an authorized task needs to restore established access. Ordinary discovery and utilization do not require this reference. Root owns workspace identity, resource resolution, initialization, managed guidance and permissions.

## Purpose and resource

Maintain the knowledge future agents need to discover, use and re-establish expected external service access, not the runtime environment itself. Cover services and useful external capabilities such as Jira, GitLab, Supabase, Azure, GitHub or web search. REST, MCP, CLI, SDK, native connectors and other approved mechanisms are equally valid; preserve working approaches. Python purpose environments, personal scripts, project application infrastructure and skill installation retain their existing owners.

Use one free-form Markdown environment record at the confirmed existing location or the proposed `.work-context/environment.md` for a new resource. Group by workspace or relevant project when useful. Capture only established expected access and durable information that helps future agents: purpose, applicable project/account/tenant/resource or access boundaries, known working access methods, safe configuration locations, authentication/setup instructions or authoritative links, and useful limitations or checks. No mandatory fields, index, schema, protocol or provider preference. Link canonical configuration or documentation rather than duplicating it. Distinguish expectations, known alternatives and unverified suggestions; do not turn every encountered service into a standing expectation.

Never record credentials, tokens, passwords, private keys, secret-bearing URLs, raw authentication output or full sensitive configuration. Record non-secret references and authentication procedures only where permitted. Respect employer confidentiality and separate workspace/account boundaries, including local storage, Git history and external transfer. An expected connection is not a grant of access or operation authority.

## Ordinary utilization and missing access

Before work that could materially benefit from established external access, consult the relevant environment entries, discover actual session tools or approved access methods and use an appropriate available route within the task's authority. Prefer existing working access; do not require the maintenance skill, a full inventory scan or a separate probe when actual authorized use is sufficient evidence. Verify the intended account/project/tenant and permission scope before consequential operations; a working connection to the wrong target is not success.

If expected access is missing or fails, distinguish absent tooling, configuration, authentication, permissions, wrong target, connectivity and harness limitations as relevant. Check a known approved alternative if appropriate; do not bypass policy or substitute another account/project. For necessary restoration during authorized work, load root and this reference. Diagnose and perform only already-authorized safe repair; otherwise identify the specific human action or approval needed. Ordinary utilization does not authorize durable record changes, new grants, installation, harness/security changes or external mutations. Continue unaffected work where possible; do not fabricate results or silently replace direct evidence with assumptions.

## Requested setup, check, repair or sync

Select the relevant scope (workspace or named project/service) and operation; combined requests are valid.

- **Check environment:** compare expected access against actual availability using bounded, harmless checks or sufficient recent direct evidence. Read-only; report specific missing, unusable or unverified access, not a persisted health snapshot.
- **Setup / repair environment:** inspect existing access first, reuse working mechanisms, identify missing prerequisites and establish or restore approved connections using existing native/vendor-supported procedures. Consult current authoritative setup guidance if needed. Apply changes only within explicit or established scoped authority; the request is not blanket permission for machine installs, harness settings, new accounts/grants, permission expansion or policy changes. Ask for necessary human-owned authentication/approval via the appropriate secure mechanism; never ask for secrets in chat or print them. If session restart, interactive login or unavailable tools prevent completion, report the exact next step and verify afterward when possible. Do not reinstall working tools.
- **Sync environment:** during authorized maintenance capture useful established access and setup knowledge, reconcile directly affected obsolete entries and preserve confirmed restrictions. Do not remove an expected capability merely because the current session cannot access it. First initialization or routing changes follow root approval; use existing compatible knowledge without creating competing records. A check-only or ordinary execution request does not authorize record writes.

A general maintenance pass may select Environment only when directly relevant durable knowledge warrants it; no automatic full connection audit, installation or recovery. New-machine or harness setup is request-led: the record tells the agent what to restore, but credentials and actual configuration do not travel with it by implication. No provisioning framework, synchronization, credential vault, health dashboard, scheduled monitoring, mandatory timestamps or startup checks.

## Completion and guidance

For setup/repair, verify the affected connection with the least invasive useful operation against the intended target where authorized; distinguish tool presence, authentication, sufficient task access and unverified claims. Report actual usable access, remaining blockers and specific human steps; do not claim broad permissions or successful recovery from configuration alone. For sync, verify changed content and relevant routing without exposing secrets. No extra receipt for routine successful use.
