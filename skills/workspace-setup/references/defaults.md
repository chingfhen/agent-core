# Creation-time defaults

Use these only during approved guidance initialization/update. Each owning skill
defines its own markers, labels, minimal activation cue, and first-use procedure.
Preserve existing human wording during maintenance; managed does not mean regenerate.

## Always-loaded admission

Include confirmed resource locations, a few selective entry points with when-to-read
cues, and essential before-action constraints. Keep task navigation in INDEX.md,
project detail in docs, KB content indexes in the KB, and environment compatibility
in recipes/runtime. The skills own procedures. Do not add a skill inventory,
environment snapshot, or duplicated workflow to guidance.

## One optional startup cue

During approved initialization/update, propose this instruction separately from
the owner sections and obtain approval for it. Do not repeat it in every block or
reinsert it during routine section maintenance:

```markdown
In the first response, identify applicable guidance as `AGENTS.md: <path(s)>`.
Report only actual applicable paths; this is recognition, not proof of compliance.
```

Use one instruction for the guidance scope. Preserve an existing approved cue.
Never fabricate an absent file or promise that existing sessions reload live.

## Availability and migration

Availability comes from exposed session metadata, not a retained catalogue or
manifest. All Agent Core skills permit model invocation; human requests in natural
language can activate request-only workflows. Loading a skill does not authorize
its side effects beyond the request and local rules.

For legacy central blocks, preserve customized Use for/Behavior text and repository
annotations. Propose relocation of that text only within an explicitly approved
migration; do not silently delete it merely to make guidance shorter. New owner
sections must not compete with an old authoritative destination table.
