## Executive Recommendation Criteria

The Agent OS `html-brief` / `html-explainer` skill converts raw technical contexts into interactive, human-readable documents. This research establishes six core criteria to guide its implementation:

| Decision Axis | Recommendation | Target State for Agent OS |
| --- | --- | --- |
| **Skill Shape** | **Derived View Generator** | A pure functional transformer. The skill reads structured data and outputs static web files. It contains no native persistence layers. |
| **Source Inputs** | **Canonical Markdown/Mermaid** | Core files (`docs/*.md`, `tasks/*.md`, `*.mmd`) remain the single source of truth for mutations. The skill treats them as read-only. |
| **Output Location** | **Isolated Build Directory** | Output runs go directly to `.agentos/artifacts/html/`. This decouples rendering noise from main code tracking branches. |
| **Safety Rules** | **Networkless Sandbox Execution** | Enforces a strict, localized Content Security Policy (CSP). It disables external connections and restricts iframe script capabilities. |
| **Artifact Lifecycle** | **Transient & Disposable** | Artifacts are ephemeral by default. They can be auto-regenerated by file watchers or overwritten during terminal execution sessions. |
| **Non-Goals** | **No Web Application Engineering** | Out of scope: State persistence engines, multi-route applications, server-side code execution, and real-time database hooks. |

## Adjacent Proven Patterns

### Automated Report & PDF Generation (Fast.io Architecture)

* **Layout Expressiveness**: Large Language Models (LLMs) are highly performant at writing valid HTML and CSS blocks compared to writing coordinate-based PDF positioning code `[COMMUNITY]`.
* **Downstream Compilers**: Agents routinely output semantic HTML, passing it to tools like `WeasyPrint` or `wkhtmltopdf` inside execution sandboxes to generate clean PDF documentation `[COMMUNITY]`.
* **The Citation Protocol**: To avoid narrative hallucinations, reporting agents append machine-readable data tracking hashes back to exact rows or files for all figures displayed in the HTML layout `[COMMUNITY]`.

### Artifact Sharing Gateways (PreviewShip Model)

* **Decoupled Deploys**: Rather than pushing source files directly, agent pipelines zip built directories (`dist/`, `out/`, `public/`) containing an `index.html` file alongside completely self-contained static assets `[COMMUNITY]`.
* **Tool Integrations**: This deployment is typically automated via standalone CLI tools or specialized MCP server extensions `[COMMUNITY]`.

## Canonical Source vs Derived Artifact Models

To ensure the codebase stays easy for models to modify, Agent OS must separate editable source truth from highly visual presentations.

```
+------------------------------------------------------------+
|                     CANONICAL SOURCES                      |
|  - docs/*.md (Specs)             - tasks/*.md (Kanban)     |
|  - engineering/*.ts (Codebases)  - architecture/*.mmd      |
+------------------------------------------------------------+
                              |
                              v
+------------------------------------------------------------+
|                    AGENT OS SKILL PIPELINE                 |
|  1. Parse Source Markdown        2. Resolve Data Cross-Refs|
|  3. Render Markdown to HTML      4. Embed Inline Assets    |
|  5. Apply Security Sanitization  6. Inject Stale-Checker   |
+------------------------------------------------------------+
                              |
                              v
+------------------------------------------------------------+
|                    DERIVED ARTIFACTS                       |
|             .agentos/artifacts/html/brief.html             |
|   (Read-Only, Fully Inlined, Non-Canonical Presentation)   |
+------------------------------------------------------------+

```

| Metric / Feature | Canonical Source (`docs/`, `tasks/`, `.mmd`) | Derived Artifact (`.agentos/artifacts/html/`) |
| --- | --- | --- |
| **Format** | Pure semantic Markdown, Mermaid text strings. | High-fidelity inline HTML, CSS, and embedded SVGs. |
| **Model Mutability** | **High**. Simple for LLMs to patch via standard diffs. | **Low**. Models struggle to patch nested HTML tags accurately. |
| **Git Tracking** | Tracked continuously in source control. | Excluded via `.gitignore` (except for major milestones). |
| **Human Utility** | Good for text drafting; low layout clarity. | Excellent for visual walkthroughs and navigation. |
| **Data Interactivity** | Static text strings. | Tabbed views, column sorting, and collapsible areas. |

## Output Location and Lifecycle Conventions

### 1. Directory Structure Configuration

```
project-root/
├── docs/                      # Canonical Markdown Documents
├── tasks/                     # Canonical Task Lists
├── .gitignore                 # Configured to filter transient output noise
└── .agentos/
    └── artifacts/
        └── html/              # Output Target Directory
            ├── .cache/        # Performance optimization assets
            ├── brief_abc123.html
            └── current_explainer.html -> brief_abc123.html

```

### 2. Git Automation Guidelines

The `.agentos/` directory is blocked from normal version tracking by default:

```
# .gitignore addition
.agentos/artifacts/html/*
!.agentos/artifacts/html/milestones/  # Explicitly preserve designated milestone saves

```

### 3. Execution & Regeneration Hooks

* **On-Demand Invocations**: Triggered via user CLI commands: `/html-brief --input=tasks/TODO.md`.
* **Automated Watchers**: Monitored by local file event loops. If files inside `tasks/*.md` change, the skill recreates `current_explainer.html` in the background.
* **Session-Bound Cleanup**: A cleanup rule checks artifact runs on startup, deleting generated HTML files older than **7 days** to manage local disk space.

## Safety and Trust Boundaries

### 1. The Networkless Content Security Policy (CSP)

Every generated HTML document must inject a strict CSP header inside its `<head>` element to prevent malicious code execution or data leaks `[OFFICIAL]`:

```html
<meta http-equiv="Content-Security-Policy" content="
  default-src 'none';
  script-src 'unsafe-inline';
  style-src 'unsafe-inline';
  img-src data: btoa;
  connect-src 'none';
  frame-src 'none';
  base-uri 'none';
  form-action 'none';
">

```

> **Security Impact**: This configuration blocks external HTTP requests (`fetch`, `XHR`, `WebSockets`), completely neutralizing common token exfiltration vectors `[OFFICIAL]`.

### 2. Local View Framing & Sandboxing

When rendering briefs inside local developer environments or IDE extension panes, use an explicit sandboxed iframe wrapper:

```html
<iframe 
  src="brief_abc123.html" 
  sandbox="allow-scripts" 
  security="restricted">
</iframe>

```

### 3. Out-of-Sync / Stale Detection Flags

To prevent human architects from making design decisions based on outdated reports, the skill injects build metadata attributes directly into the wrapper template:

```html
<div id="agentos-metadata" 
     data-built-at="2026-06-25T14:40:45Z" 
     data-source-hash="e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855">
</div>

```

A lightweight internal JavaScript function compares the current project file system state against `data-source-hash`. If the codebase has moved forward, it displays a persistent warning banner at the top of the viewport: ⚠️ **STALE PRESENTATION LAYER — Code changes have occurred since generation.**

### 4. Code Block Integrity Toggles

To ensure model compilation bugs are not hidden by clever CSS layout styling, every rendered code element must provide a clear view alternative:

```html
<div class="code-container">
  <button onclick="toggleRaw(this)">View Plaintext Source</button>
  <pre class="rendered-code"><code>...</code></pre>
  <textarea class="raw-source" style="display:none;">...</textarea>
</div>

```

### 1. Inlining Constraints & Resolution

* **CSS Embeds**: Global utility classes are wrapped cleanly inside single `<style>` fields.
* **Vector Asset Injections**: Standard image tags pointing to external endpoints are prohibited. Diagrams generated via Mermaid are converted into standard embedded inline `<svg>` blocks to comply with the strict CSP rules `[OFFICIAL]`.

### 2. Layout Structure & Theming Rules

* **Fluid Layout Grids**: Uses simple flexbox structures designed to fit comfortably in both narrow IDE sidebars and ultra-wide monitor arrangements.
* **Color Theme Synced Styles**: Implements theme variables that adapt smoothly to the parent coding workspace environment:
```css
:root {
  --bg-color: canvas;
  --text-color: canvastext;
  --accent-color: #007acc;
}
@media (prefers-color-scheme: dark) {
  :root { --accent-color: #0098ff; }
}

```



### 3. Zero-Dependency Interactivity

* **Pure CSS Accordions**: Toggles presentation detail states safely using the browser-native `<details>` and `<summary>` components.
* **Vanilla JS Tab Managers**: Implements layout tab selection via minimal event listeners:
```javascript
document.querySelectorAll('.tab-trigger').forEach(btn => {
  btn.addEventListener('click', () => {
    document.querySelectorAll('.tab-panel').forEach(p => p.style.display = 'none');
    document.getElementById(btn.dataset.target).style.display = 'block';
  });
});

```


* **Print Layout Support**: Embedded print directives clean up the canvas, automatically removing UI navigation elements and expanding collapsed details sections for clean PDF printing:
```css
@media print {
  .tab-trigger, .ui-controls, .stale-banner { display: none !important; }
  details { display: block !important; }
  details[open] > summary ~ * { display: block; }
}

```

## Task/Docs Visualization Patterns

The transformation pipeline matches raw file context onto specialized user interface layouts:

```
[Markdown Source Context]                 [Inlined HTML Visualization Surface]

tasks/TODO.md --------------------------> Tabbed Kanban Columns (Todo/Doing/Done)
docs/architecture/spec.md --------------> Navigation Hierarchy Outline Sidebar
architecture/flow.mmd ------------------> Direct Embedded Inline Interactive SVG Grid
git diff HEAD~1 ------------------------> Split-Panel Syntax Colorized Code Diffs

```

### Component Architecture Details

#### Task Management Arrays

Converts standard markdown list indicators (`- [ ]`, `- [x]`) into a grouped multi-column layout card grid. Columns automatically calculate and display current velocity ratios (e.g., `Done (5/12)`).

#### Code Review Explanations

Converts native git structural text arrays into clear side-by-side comparison tables. Line changes link directly to inline code documentation popups explaining complex architectural changes.

#### Performance & Coverage Metrics

Transforms abstract test coverage numbers and benchmarks into semantic SVG status meters, highlighting systemic bottlenecks without importing external graphing dependencies.

## Recommended Agent OS Skill Shape

### 1. Unified Configuration Schema

The skill defines its runtime options through a strict Pydantic declaration structure:

```python
from pydantic import BaseModel, Field
from typing import List, Optional

class HtmlBriefSkillConfig(BaseModel):
    skill_name: str = "html-brief"
    input_directories: List[str] = Field(default=["docs", "tasks"])
    output_directory: str = Field(default=".agentos/artifacts/html")
    max_file_size_bytes: int = Field(default=16777216)  # Strict 16 MiB boundary
    embed_svg_diagrams: bool = Field(default=True)
    enforce_strict_csp: bool = Field(default=True)
    theme_preset: str = Field(default="system-adaptive")
    auto_watch_mode: bool = Field(default=False)

```

### 2. Skill Pipeline Routing System

```
[User Action or Watcher Flag] 
       |
       v
[/html-brief Trigger Checked]
       |
       +---> Check Target Inputs? (e.g., docs/ changed)
       |
       v
[Read Markdown File Arrays]
       |
       v

       |
       +---> Render Markdown -> Core Structural HTML
```

## Unresolved

1. **Local Network Asset Exposure**: While the custom CSP layout blocks standard internet requests completely, it remains open if operating inside custom local proxy loops or specialized enterprise configurations requires extra protection rules to secure sensitive file paths.
2. **Context Frame Token Limits**: For complex corporate codebases with massive folder deep-dives, generating everything inside a single, strict **16 MiB** inline target output can stress active context spaces. Tradeoffs between compressing code summaries versus dividing single briefs into smaller segmented pages require further human review.
